CLI Commands Reference

Complete manual for all command-line interface arguments, subcommands, flags, and diagnostic modes in the Persica compiler.

Command Overview

The persica binary is a single self-contained executable that handles compiling, interpreting, project scaffolding, unit testing, and static analysis:

Terminal
persica [SUBCOMMAND] [OPTIONS] [FILE]
CommandDescriptionExample Usage
persica <file.persi>Execute a standalone single filepersica app.persi
persica new <name>Scaffold a complete new projectpersica new web_api
persica initInitialize current directory as projectpersica init
persica runRun the project entrypoint in persica.tomlpersica run
persica testRun all unit tests in tests/ directorypersica test
persica check <file>Validate syntax & types without runningpersica check src/main.persi
persica --eval "<code>"Evaluate an inline snippet of codepersica --eval "print(2+2);"
persica -Read program source from standard inputcat main.persi | persica -

Project Management Subcommands

persica new <name>

Creates a new directory with a configured persica.toml, src/main.persi, and .persi_env/ local dependencies folder.

persica run

Searches for persica.toml in the current folder or any ancestor directory, configures the module resolution paths, and executes the designated entrypoint.

persica test

Scans the tests/ folder and executes every *.persi test file, reporting individual pass/fail results and an exit code for CI systems.

Static Analysis & Inspection Flags

Persica includes compiler diagnostics useful for tooling and editor integration:

Terminal
# 1. Type check without execution
persica check main.persi
# Output: "check succeeded" (exit code 0)

# 2. Dump lexer tokens
persica --tokens main.persi

# 3. Dump parsed Abstract Syntax Tree (AST)
persica --ast main.persi

Standard Input (Pipelines)

Pass a single dash - to execute code piped from another shell command:

Terminal
echo 'print("Piped execution!");' | persica -
Output:
Piped execution!

Exit Codes & Diagnostics

Persica communicates cleanly with scripts and CI pipelines via standard exit codes:

  • 0 — Success (execution or static check passed cleanly).
  • 1 — Compile or runtime diagnostic error. Details are printed to stderr in source-aware format: error[phase]: message --> file:line:col.
